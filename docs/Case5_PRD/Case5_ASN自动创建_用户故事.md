# 第一部分：MBPLAP 支线

## EP-B1：每日定时取数与建票

**用户故事：** 作为进口操作员，我希望平台每天 12:00 和 17:00 自动从 IES+ 导出当日 MBPLAP 预报清单并逐票建任务，17:00 的批次不再重复处理 12:00 已成功的票，以便每日两轮的 ASN 模板制作完全不用人工开单。

**验收要点：**

- 每日 12:00 / 17:00 定时触发（调度可配置），数据窗口=执行当日（Pre-alert creation=当日，Supplier=MBPLAP）
- **17:00 剔除逻辑**：17:00 运行前剔除 12:00 已成功运行的分单号，不重复处理（原型未实现该逻辑，见 §三 D-2）
- IES+ 进口预报批量导出成功（G1 前置），导出失败记批次台账并告警
- **预报导出登记即建票**：每归集出一个去重分单号（HAWB/BL No.）即建 Task + Run#1；当日无数据只记批次台账、不建票
- 手动批量重提交：按分单号或 Pre-alert creation 日期批量筛选提交，**进待运行队列随下一次定时运行**，撞票按分单号去重（"重提交=排队补票"与"重跑=生成 R#n+1"语义区分）

## EP-B2：发票导出与模板生成发布

**用户故事：** 作为进口操作员，我希望系统按分单号自动导出 PN 级发票清单、合并加总后填好 DSS 模板并发布到 Portal，以便我直接下载导入 DSS，不再手工合并算数。

**验收要点：**

- 按 HAWB/BL No. 批量查询 IES+ 发票信息，按 PN 级模板全部导出；导出非空且列结构校验通过（G1 数据就绪闸口），否则 FAILED 转人工
- 按合并键（发票号+Order No.+Part No.）加总数量，映射 DSS 模板 9 字段：ASN Number / Vendor BP Number（固定 191110510）/ Delivery date / SPM Part Number / Quantity / Unit（PC）/ SPM PO Number / SPM PO Item Number（本线置空）/ ETA date（Pre-alert creation+1）
- G3 模板质量闸口：9 字段必填校验（PO Item 按本线规则允许置空）、合并结果非空、勾稽无异常；不过→记差异置"有差异"待人工修正
- 逐票生成模板文件按「提单号_发票号.xlsx」命名（待 BU 确认），在 Portal 上可供下载
- 发布与归档在票终态前完成；产出即边界——导入 DSS、EDI 下发、开票核对不纳入

## EP-B3：任务跟踪与整单重跑

**用户故事：** 作为进口操作员，我希望在工作台和任务中心看清每天两轮跑批的每票状态，失败的票能一键重跑，以便只处理异常、恢复不求人。

**验收要点：**

- 工作台按 Case5-MBPLAP 展示统计卡（总任务数/已完成/执行中/待人工处理）与调度信息条（今日 12:00/17:00 两批次），点卡穿透任务中心
- 任务中心：状态 chips（待人工处理=待上传∪有差异∪失败聚合）、任务日历、执行时间/单号（HAWB/BL No.）筛选、批量下载/批量重跑/导出
- 任务详情：节点轨迹（原型演示为 导出预报清单 → 导出发票信息 → 填入DSS导入模板 3 节点）、字段面板（来源/置信度/原文定位）、证据附件（WORM）、R# 历史切换只读、DSS 模板文件可下载
- 重跑：仅整单重跑（无节点级），生成 R#n+1（固化配置快照+携带生效修正值）；同票互斥幂等、执行中跳过；**无对外系统写入，故无 MANAGER 门槛**，操作员即可触发（OPEN-A13）
- MBPLAP 重跑无需人工上传：系统自动从 IES+ 重新导出数据

# 第二部分：X-entry 支线

## EP-X1：送货邮件收单建票

**用户故事：** 作为进口操作员，我希望报关代理的送货邮件一到公邮就自动建票，相关 PO 邮件自动归并到同一票，以便不再人工盯邮箱、对运单。

**验收要点：**

- 邮件**直发 Portal 公邮 asn@mb.cn**（演示取值，正式地址 OPEN-A4），不做转发；监听两条规则：报关代理邮件（发件人 \*@bjfcl.com + 主题含"快件签收单" + Excel 附件必需）、PO 邮件（主题/正文含 PO 号 + SPM 截屏图片附件）
- **送货邮件收单即建票**：命中即解析 AWB 建 Task + Run#1；PO 邮件按 PO 号归并到同 AWB 票，**只归并不建票**；同 AWB 重复邮件保留最新版
- 附件解析不出 AWB 转人工；孤立 PO 邮件暂存，超期（建议 24h，OPEN-A17）生成站内提醒
- PO 邮件未到时票挂"待上传"等齐（G2 闸口），阻断票同样有 Task、可在任务中心被看到
- X-entry 从触发到产出可接受半天时延

## EP-X2：大表查询与 PO 判定阻断

**用户故事：** 作为进口操作员，我希望系统自动拿运单号去诊断仪大表查 PN、数量、ID No. 并反查 MBPTS PO，PO 为空时立即阻断并告诉我，以便 PN/数量不再人工查表算错、PO 缺失不再无人感知。

**验收要点：**

- 按 AWB 查诊断仪大表（D 列 PN / F 列 Qty 加总 / J 列 ID No. / M 列 PO / N 列 AWB，列名优先、列号兜底）；Run 启动时固化大表快照
- G1 数据就绪闸口：AWB 命中且 PN/QTY/ID No. 齐备才放行，否则 FAILED 转人工
- **PO 判定硬阻断**：ID No. 反查 M 列 PO 为空→本票阻断置"待上传"（need=idno），生成站内提醒（附当前 ID No. 值），等待 PO 补上后人工录入续跑（EP-X3）
- 邮件 Quantity ≥ 大表加总不校验；小于则记 Remark 转人工（兜底流程 OPEN-A3）

## EP-X3：等齐补齐与人工协同

**用户故事：** 作为进口操作员，我希望阻断票有明确的补录入口——录 ID No.、补传发票、确认等 PO 邮件——补齐后能自动或一键续跑，以便异常票有闭环、不积压。

**验收要点：**

- 阻断票顶部横幅说明原因并可"前往处理"直达对应节点；站内提醒同步生成
- **录入 ID No.**（诊断仪大表 J 列，4~8 位校验）：在"捕捉PO邮件"节点录入，留痕（旧值→新值）；录入后"等待下一次运行继续流程"；未录入时整单重跑被拦截并提示先录入
- **进口发票补传**：按 AWB 查系统库未找到发票时（ASN Number 与 Shipment Date 无法取值），引导到上传中心补传（PDF ≤20MB），提交后自动触发整单重跑
- **等 PO 邮件**：PO 邮件未到挂起票可"确认继续等待"或"标记无效"（是否可撤销 OPEN-A13）
- 所有补录/修正仅留痕不审批，随下次运行生效并跨 Run 继承；并发补录同一票按版本校验防冲突（OPEN-A18）

## EP-X4：顺次收货与模板生成发布

**用户故事：** 作为进口操作员，我希望系统按 SPM 截屏的 Item 行自动做顺次收货拆行并填好 DSS 模板发布，以便多 Item 分摊不再手工算错。

**验收要点：**

- OCR 识别 PO 邮件 SPM 截屏取 Item 列；同一 Material 多 Item 时从第一行 Item 起按剩余量**顺次消耗拆多行**（如 100=Item100×20+Item200×80）
- 按 AWB 查系统库进口发票取 ASN Number（Our delivery note number）与 Shipment Date
- 映射 DSS 模板 9 字段：来源=大表/PO 邮件/发票，Vendor BP 固定 191110260；G3 模板质量闸口校验必填与勾稽
- 模板按「PN_日期.xlsx」命名（待 BU 确认）在 Portal 发布
- **收货记录登记**：自动（RPA）与手工收货并列、手工不覆盖自动，自动行按 AWB+PO+Item 去重；收货记录含已收/订购/剩余，BU 可搜索导出（订购量数据源 OPEN-A14）

## EP-X5：任务跟踪与重跑

**用户故事：** 作为进口操作员，我希望在工作台和任务中心看清每票送货邮件的处理状态，阻断和失败的票能按指引恢复，以便半天时延内结果可预期。

**验收要点：**

- 工作台按 Case5-X-entry 展示统计卡（含待人工处理聚合），点卡穿透任务中心
- 任务中心：状态 chips、任务日历、执行时间/单号（AWB No.）筛选、批量下载/批量重跑/导出
- 任务详情：节点轨迹（原型演示为 捕捉报关代理邮件 → 捕捉PO邮件 → 填入DSS导入模板 3 节点）、字段面板（含 SPM 截屏 OCR 字段与原文定位）、收货记录证据区、R# 历史切换只读
- 重跑：仅整单重跑（无节点级），生成 R#n+1（配置快照含模板+大表+规则版本、携带补录/修正值）；无 MANAGER 门槛（OPEN-A13）；ID No. 未录入的阻断票先拦截提示
- X-entry 重跑无需人工上传：系统自动重读诊断仪大表、公邮邮件与系统库发票

# 第三部分：两线共用

## EP-S1：配置维护与上传中心

**用户故事：** 作为配置维护者，我希望 DSS 模板、诊断仪大表与调度参数在线版本化维护；作为进口操作员，我希望上传中心集中承载发票补传、手工收货、录入 ID No. 三类人工处置，以便配置不散落、处置有入口。

**验收要点：**

- 配置中心：DSS 导入模板两条（MBPLAP/X-entry 各一，9 列相同、Vendor BP 不同）+ 诊断仪大表 + 调度配置，版本化管理（上传新版本 v+1，旧版本可下载）
- 配置生效语义=Run 启动快照（建议，OPEN-A16），历史 Run 不重解释
- 上传中心三 Tab：进口发票补传（提交后自动触发整单重跑）/ 手工收货录入（PO 10 位+Part No.+数量，带联想校验）/ 录入 ID No.（4~8 位，随下次运行续跑），另附收货记录抽屉与提交记录
- 任务详情"去处理"带任务上下文自动定位上传中心对应 Tab 并锁定关联任务
- 邮件中心仅 X-entry 两条监听规则可维护（启停/编辑写审计）；**Case5 无邮件模板**（不发通知邮件，结果=Portal 下载模板文件），触达业务的通道=站内提醒（5 类模板，点击跳详情）

## EP-S2：存档与审计合规

**用户故事：** 作为审计员，我希望每票产出与原件按时间戳目录归档、只增不改，全量证据链与审计日志只读可查，以便合规审查有据可依。

**验收要点：**

- SharePoint 归档：`<支线>\<YYYYMMDD_HHmm>\` 时间戳目录**追加写入不覆盖**，历史只读；仅归档已完成票产出（MBPLAP=模板文件；X-entry=模板+进口发票原件保持原名+报关代理附件）；同批次内重跑同名文件建议覆盖（OPEN-A15）
- 根目录单独存放诊断仪大表；Share Point 页平台内只读浏览
- 收货记录按 AWB+PO+Item 去重登记，自动/手工并列留痕
- 审计员全部页面只读，写接口服务端拒绝并记录决策；证据三类（EV-T/EV-P/EV-O）hash+WORM；审计日志五要素可搜索；关键参数（邮箱/路径/重试）配置化不硬编码、凭证不入日志
