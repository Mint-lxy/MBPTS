### 1.2 GLC 线分阶段说明

| 阶段 | 节点 | 说明 |

| 触发 | T01 | 每周一 09:00(可配置),处理上周一至周日数据 |

| 文件准备 | R05→R06 | 从暂存库取件组装文件包(含 DG 时 Shipper),填写 AVIS 模板(字段全部取自 AVIS)与 BL 模板(Container Type 单位改 `'`) |
| IES 导入 | R07→D03 | 发票信息查 MBZ → 批量导入 AVIS → 绿灯后上传 → 回写 G 列;DG 判断以收单时是否搜到 Shipper 为准 |
| DG 分支 | R08→D04→R09/E03→R10 | 按 invoice 级导出算差异(FOB 公式);找到 PDF 则核对(金额不一致以 IES 导出值为准并记录),未找到按差异值填并记"未找到 xxx 发票";FOB 填入 Others 保存 |
| 预报与 BL | R11→R12→D05 | 全选发票生成预报(信息取自提单)→ 集装箱信息导入 BL 模板 → 差异弹窗判断 |
| 差异与上传 | E04→R13 | 差异内容回写 L 列 BL different;上传 AVIS(类别 Other)/Shipper/BL 附件并保存 |
| 输出 | O01/O02/O03 | 生成台账成功;回写大表 H/K/N=Y、J 列 BL Creation;周归档文件夹齐备可查 |

### 1.4 As-Is / To-Be

| 维度 | As-Is(人工) | To-Be(平台) |
|------|------------|-------------|
| 收单 | 人工逐个搜索公邮、下载附件 | 邮件规则监听 + 统一收单 + 按 BL 号归并暂存 |
| 归档 | 人工建文件夹、改名 | 自动按 PDC/线路/运行周/票建目录,命名规则内置 |

| 异常 | 靠经验发现 | 全部异常自动识别转人工,修正留痕可重跑 |
| 回写 | 人工填写大表各列 | 平台台账为主,自动双写大表 |

## 2. 功能模块设计

> 页面与交互以 `case2页面demo\` 为原型基线;截图为静态演示态(`images/*.png`)。

### 2.1 工作台(index.html,截图 index.png)

- **布局**:侧栏导航 + 顶栏(提醒/主题/用户)+ 内容区按线路分组(GLC 欧线·OOCL / MBUSI 美线·CMA CGM)。
- **元素**:每线路 4 张统计卡——总任务数 / 已完成 / 执行中 / 待人工处理(以 BL No. 为票粒度)。
- **交互**:点击统计卡带参跳转任务中心(`from=workbench&mode=glc|mbusi&status=...`),任务中心顶部出现"来自工作台"上下文条。
- **空态/异常**:无任务时统计卡显示 0,可点击跳转空列表。

### 2.2 任务中心(tasks.html,截图 tasks.png)

- **布局**:筛选区(状态 chip + 来源筛选 + 搜索框)+ 任务表格 + 底部批量操作栏。
- **表格列**:勾选、任务编号(含 BL No.)、case、用例、触发来源、状态(当前执行)、执行次数、最近执行开始、当前环节。
- **状态集**:`执行中 / 待人工处理(有差异) / 待上传(缺件挂起) / 失败 / 已完成`。
- **操作**:导出列表(CSV)、新建任务(选线路)、勾选后批量重跑(执行中的自动跳过)。
- **规则**:任务状态取最新执行实例(Run)的状态;执行次数 = Run 数量。

### 2.3 任务详情(task-detail.html,截图 task-detail.png / task-detail-mbusi.png)

核心页,严格区分 **Task(单据)× Run(执行实例)**:

| 区块 | 内容 |
|------|------|
| 头部 | 任务号、用例、BL/HAWB、来源、当前状态、当前执行 R#N、执行次数;失败时「整单重跑」,有差异时「上传文件/整单重跑」 |
| 三层横幅 | 待上传缺件(黄)/ R#N 有差异(黄)/ R#N 失败(红) |
| Run 切换 | R#1、R#2… 历史只读,当前生效版本可操作 |
| 节点执行轨迹 | 左轨节点列表(GLC 7 节点 / MBUSI 10 节点)+ 右侧工作区 |
| 当前识别数据 | 字段名/值/来源(OCR/规则)/置信度/质量等级;**行内修正留痕**(修正仅留痕不审批,写入当前生效版本,重跑携带修正值);**PDF 原文定位**(点击定位到原文预览对应页) |
| 原文预览 | PDF 翻页/缩放,授权路径引用 |
| 步骤证据 | email/ocr/screen/table/file 五类证据,内联预览,标注 WORM 防篡改 |
| 触发历史 | 同 Case 兄弟任务,15 天热力图、成功率、平均耗时 |
| 操作日志 | 任务级全操作留痕 |

**节点编排**:
- GLC(7 节点):下载 AVIS/Shipper/BL → OCR 识别(AVIS⇄BL 交叉核对)→ 写入 AVIS 模板 → 写入 BL 模板 → 导入 AVIS 模板(DG 含 FOB 核对)→ 导入 BL 模板(预报+集装箱+台账)→ 上传原始文件(回写大表)
- MBUSI(10 节点):下载 gvShipLog → 拆分 Booking No. 子表 → 填 Shipping Log 模板 → 下载邮件附件 → OCR 识别 → 填 BL 模板并回填 Shipping Log → 导入 Shipping Log → 生成预报 → 导入 BL 模板 → 导入 BL PDF 保存

**状态流转(Run)**:PENDING → RUNNING → SUCCEEDED / DIFF_PENDING(有差异,转人工)/ WAIT_INPUT(缺件挂起)/ FAILED(失败可重跑);重跑生成 R#N+1,历史 Run 不可变。

### 2.4 邮件中心 + 规则编辑器(rules.html / rule-edit.html,截图 rules.png / rule-edit.png)

**邮件中心(rules)**:
- 邮件监听规则表(按线路分组):规则、监听邮箱、优先级、绑定流程、累计命中、启用开关;操作:试运行 / 编辑 / 新建规则。

1. **筛选条件**:规则名、监听邮箱、发件人白名单(支持 `*@域名`)、To/Cc、主题关键词、正文关键词、附件数量上下限。

## 3. 核心业务规则汇总

### R1 收单规则
- R1.1 邮件按主题关键词分类:GLC 线「AVIS」/「Shippers_Decl」/「Bill of landing」;MBUSI 线「CMA CGM - 海运提单(Seaway Bill)可供使用」。
- R1.2 命中的附件**一律先按 BL 号入暂存库并写附件台账**(状态 pending),匹配成功即处理。
- R1.3 台账 key = BL 号,**格式归一**;同 BL 重复邮件**保留最新版**。
- R1.4 GLC 线:E 列记 AVIS No.;M 列记 Shipper(**命中 Shipper 即判定 DG**)。

### R2 归档规则
- R2.1 PDC 由 Customer code 查配置表映射;**未命中建 Other 文件夹**,文件存入并在异常反馈列记录,流程继续。
- R2.2 命名:GLC 票文件夹 `Shippers Ref + OOLU + BL No. + ETA <YYYY.MM.DD>`,DG 票追加 `DG`;MBUSI `<BL> ETA <YYYY.MM.DD>`。
- R2.3 文件重命名:BL → `BL_<BL号>`;Shipper → `shippers_Decl_BL`。
- R2.4 归档根为配置项,默认 SharePoint,兼容 T 盘过渡。

### R3 齐套与挂起规则
- R3.1 GLC 齐套 = AVIS + BL 均按 BL 号归并到手(DG 票另需 Shipper)。
- R3.2 缺 AVIS:单列一行,P 列记"未找到对应 AVIS,请确认是否漏发",该票挂起,**人工确认后再跑**。
- R3.3 MBUSI 漏数(收到 PDF 但大表未登记):**不删除不处理**,台账保持 pending,等美表补登记(created 更新不回溯),下轮筛选捕获后从台账取回附件续跑。
- R3.4 BL 与 AVIS 存在 2~3 周时间差,齐套判断必须跨周归并。

### R4 模板规则
- R4.1 AVIS 模板字段**均从 AVIS 获取**;BL 模板字段取自 BL,**Container Type 单位改 `'`**。
- R4.2 Shipping Log 基础字段取自网站导出(gvShipLog),**Container VOL(m³)/Load(KG) 取自 BL**。
- R4.3 预报信息均来源于提单;港口名经 **IES Port 对应表**转换;船名航次直接 COPY。
- R4.4 模板版本化管理,上传新版本即生效,历史版本可查。

### R5 IES 执行规则
- R5.1 **绿灯(就绪指示)后方可上传**;必填数据上传前校验,不上传不完整模板。
- R5.2 DG 票:按 invoice 级导出,差异公式 `FOB = Total − Goods − Packing − Insurance − Freight − DGR`,**差异 ≠ 0 即需处理**。
- R5.3 有 PDF 发票但金额不一致:**以 IES 导出 FOB 值为准**,并在异常反馈列记录;未找到发票 PDF 按 Excel 差异值填写并记"未找到 xxx 发票"。
- R5.4 差异弹窗内容**完整捕获**回写 L 列「BL different」;MBUSI 有差异时 IES **不生成台账**。
- R5.5 附件上传类别:AVIS 选 **Other**;全部传完点保存。

### R6 回写规则(双写,平台台账为主)
| 列 | 内容 |
|----|------|
| E | AVIS No. |
| G | AVIS 上传成功 |
| H/K/N | PDF(三类)上传成功 = Y |
| J | BL Creation(本票全部创建完成) |
| L | BL different(差异内容) |
| M | DG 标记(Shipper) |
| P | 异常情况反馈 |

### R7 重跑规则
- R7.1 重跑**不得产生重复**行/文件夹/上传(去重键 + 防重)。
- R7.2 Run 不可变;整单/节点/批量重跑均生成 R#N+1,**携带人工修正值**。
- R7.3 执行中任务跳过批量重跑;美表漏数票补登后**从检查点续跑**,删除 IES 已生成预报由人工完成(MBUSI BRD 异常流程)。

### R8 权限与审计规则
- R8.1 四角色职责分离:**主管无字段修正权,操作员无对外确认权**。
- R8.2 修正仅留痕不审批(UC34 全场景无人工审批),修正取值写入当前生效版本。
- R8.3 全部操作写审计日志;证据(trigger/process/operation 三类)带 hash,**WORM 防篡改**。
- R8.4 配置(邮箱/路径/重试/等待时间)**不得硬编码**;凭证安全存储且不入日志。

## 4. 数据模型(逻辑模型,Q13)

### 4.1 实体清单

| # | 实体 | 说明 | 关键字段 |
|---|------|------|---------|
| 1 | MailRule 邮件规则 | 监听规则 | id、名称、线路、监听邮箱、发件人白名单、主题/正文关键词、附件数量区间、附件角色[角色+正则+必需+多份]、绑定流程、去重键、优先级、启停 |
| 2 | AttachmentLedger 附件台账 | 暂存附件登记(key=BL 号) | BL 号(归一化)、角色、文件名、接收时间、来源邮件、状态(pending/processed)、版本(同 BL 留最新) |
| 3 | StagingFile 暂存文件 | 暂存库文件引用 | BL 号、文件类型、存储路径、hash |
| 4 | Task 任务 | 业务单据(票粒度) | 任务号(T-BL号)、caseId、线路、BL/HAWB、触发来源(定时/手动创建/手动触发)、当前状态、当前 Run 号 |
| 5 | Run 执行实例 | 一次执行(不可变) | Run 号、Task id、起因、状态、开始/结束、耗时、携带修正版本 |
| 6 | NodeExecution 节点执行 | Run 内节点轨迹 | Run id、节点序号、节点名、状态、起止、输出摘要 |
| 7 | FieldResult 字段结果 | 解析字段 + 置信度 + 修正 | 节点 id、字段名、原值、来源(OCR/规则)、置信度、质量等级、修正值、修正人、修正时间、原文定位(页/坐标) |
| 8 | Evidence 证据 | WORM 留痕 | 类型(trigger/process/operation)、子类型(email/ocr/screen/table/file)、路径、hash、Run/节点关联 |
| 9 | ConfigTemplate 模板配置 | 导入模板/对应表 | 配置项、线路、当前文件、版本、更新时间、状态、列定义 |
| 10 | RefTable 对应表 | PDC / IES Port | 类型、键、值、备注、维护人、生效版本 |
| 11 | WritebackRecord 回写记录 | 大表双写 | BL 号、列号(G/H/J/K/L/M/N/P)、值、写入时间、结果 |
| 12 | Notification 站内提醒 | 成功/异常提醒 | 类型、标题、关联任务、已读、时间 |
| 13 | AuditLog 审计日志 | 全操作留痕 | 时间、操作人、动作、对象、入口、详情 |

### 4.2 核心关系

```
MailRule 1─n AttachmentLedger(经邮件命中)
Task 1─n Run 1─n NodeExecution 1─n FieldResult / Evidence
Task n─1 AttachmentLedger(经 BL 号)
Task 1─n WritebackRecord
ConfigTemplate / RefTable 被 NodeExecution 引用(按版本)
```

### 4.3 状态机

- **Task**:执行中 → 已完成 / 有差异(待人工)/ 待上传(缺件)/ 失败;人工处理(修正/上传/确认)→ 重跑 → 执行中。
- **Run**:PENDING → RUNNING → SUCCEEDED / DIFF_PENDING / WAIT_INPUT / FAILED。
- **AttachmentLedger**:pending → processed(pending 票可被下轮调度重新捕获)。

## 6. 错误码

| 码 | 场景 | 处理 |
|----|------|------|
| E1001 | 规则校验失败(正则/附件角色缺失) | 阻断保存,提示字段 |
| E1002 | dry-run 样本邮件不可用 | 提示重新选择样本 |
| E2001 | 模板上传校验失败(扩展名/>20MB) | 阻断上传 |
| E2002 | 模板版本与流程不兼容 | 阻断并提示回退版本 |
| E3001 | IES 导入差异(弹窗) | 捕获差异 → L 列 → 转人工 |
| E3002 | IES 上传失败/超时 | 记录错误,支持检查点重试 |
| E4001 | 暂存缺件(不齐套) | 任务置 WAIT_INPUT 挂起 |
| E4002 | 重复 BL(重跑去重命中) | 跳过并记录,不产生重复 |
| E4003 | PDC/ETA 缺失 | 不建不明确文件夹,转人工 |
| E5001 | 权限不足(越权操作) | 拒绝 + 审计记录 |
| E5002 | 大表回写失败 | 入回写队列重试,告警 |
