# 第一部分：GLC 线（欧线 · OOCL）

## EP-G1：每周定时收单与归档建票

**用户故事：** 作为业务操作员，我希望平台每周一自动从 Portal 公邮收取上周的 AVIS、Shippers_Decl、BL 三类邮件，按 BL 号归并建票并归档，以便不再人工搜邮件、建文件夹、登台账。

**验收要点：**

- 每周一 09:00（可配置）定时触发，处理上周一至周日数据窗口；另支持工作台"立即补跑本周批次"（同窗口去重）与任务中心手动建票（从 N2 起跑）
- 三条监听规则分类收单：AVIS（主题含 AVIS，附件 `Avis_数字.pdf`）、Shippers_Decl（指定发件人 mbox-006-gsp-lsa-vds2）、BL（主题含 Bill of Landing）
- 附件一律先按 BL 号入暂存台账（pending），同 BL 重复邮件保留最新版；大表 E 列回写 AVIS No.
- **收单即建票**：每个去重 BL 号生成一票 Task + Run#1，齐套与否不影响建票（齐套只是 G1 状态闸口）
- Customer code 查 PDC 对应关系表归档；**未命中建 Other 文件夹并在异常反馈列记录，流程不阻断**
- 票文件夹按 `Shippers Ref + OOLU + BL No. + ETA [+ DG]` 命名，BL/Shipper 附件按规范重命名

## EP-G2：字段识别与 AVIS⇄BL 交叉核对

**用户故事：** 作为业务操作员，我希望系统自动识别 AVIS 与 BL 上的字段并互相核对，低置信或不一致时停下来等我确认，以便导入 IES+ 的数据不出错。

**验收要点：**

- OCR 抽取 16 项字段（AVIS No. / Customer code / BL No. / 起讫港 / ETA / 船名航次 / 箱号 / 箱型 / 封号 / 件数 / VOL / Load / MBZ 等），每字段带来源、置信度与原文定位
- AVIS⇄BL 交叉核对：箱号、封号完全一致，VOL / Load / 件数在容差内勾稽（容差值 OPEN-G13）；不一致→字段金色高亮、任务置"有差异"停 G2 待人工
- G2 质量闸口：全部字段置信度 ≥ 阈值（建议 0.85，OPEN-G23）且交叉核对通过才放行
- PDC 由 Customer code 经对应关系表推导（规则字段，标注"无定位"及原因）
- DG 标识在齐套判断时按"是否归并到 Shippers_Decl"定版并回写大表 M 列，不在收单时判定

## EP-G3：模板生成与 IES+ 导入

**用户故事：** 作为业务操作员，我希望系统自动填好 AVIS、BL 两张导入模板并导入 IES+ 生成预报和台账，遇到差异弹窗记录下来但不停机，以便每票处理不中断、全程有痕迹。

**验收要点：**

- AVIS 模板 7 列按配置口径取数（AVIS PDF 全取 / gvShipLog+提单双口径可配置，OPEN-G21）；BL 模板 9 列取自提单 PDF，单位归一（40HQ→40'、去空格、欧式小数转换）
- 导入 AVIS：IES+ 按 MBZ 查发票 → 批量导入 → G3 绿灯闸口，绿灯才允许上传；不过则 FAILED 转人工
- DG 票额外执行 FOB 处理：价格差异 = Total − Goods − Packing − Insurance − Freight − DGR，核对 PDF 发票后填入 Others 保存
- 导入 BL：全选发票生成预报 → 集装箱信息导入 → **差异弹窗完整捕获并回写大表 L 列「BL different」，流程不阻断**；仅弹窗无法解析才置失败转人工
- 附件上传 IES+ 文档资料（AVIS→Others 类别，DG 票加传 Shipper），全部传完保存并回写大表 H/K/N/J 列
- 对外动作（FOB 已保存 / 预报已生成 / 附件已上传）发生后，整单重跑仅 MANAGER 并弹确认（逐项列后果+勾选知悉）

## EP-G4：缺件挂起与差异人工协同

**用户故事：** 作为业务操作员，我希望缺件票和差异票在任务详情里有明确的处理区，补传后能自动续跑，以便异常票有闭环、不积压。

**验收要点：**

- 缺件票（缺 AVIS 或 BL，DG 票缺 Shipper）：照样建票置"待上传"挂起，大表 P 列记异常（如"未找到对应 AVIS，请确认是否漏发"）；同 BL 跨周归并等待，支持 2~3 周时差
- 任务详情缺件处理区三操作：补传（通过后自动续跑）/ 确认继续等待 / 标记无效关闭（撤销口径 OPEN-G11）
- 差异票（交叉核对不过或低置信）：字段金色高亮，修正留痕后节点级重跑；修正仅留痕不审批
- IES 差异弹窗票：L 列已回写、终态"有差异"待线下核对；重跑无差异则终态转已完成（L 列是否清空 OPEN-G28）
- PDC 未命中的票：落 Other 并记异常，从异常提示直达配置中心补维护对应关系表后重跑根治

## EP-G5：任务跟踪、核查与重跑

**用户故事：** 作为业务操作员，我希望在工作台和任务中心按运行周掌握每票状态，在详情页核对字段与原文，并能按需重跑，以便日常只盯异常票、处理有依据。

**验收要点：**

- 工作台按 Case2-GLC 展示统计卡（总任务数/已完成/执行中/待人工处理）与调度信息条，点卡穿透任务中心并自动带筛选
- 任务中心：状态 chips（"待人工处理"=待上传∪有差异∪失败的聚合口径）、任务日历按日定位、库房（PDC）/单号（AVIS No.）/执行时间组合筛选、批量下载/批量重跑/导出/新建任务
- 任务详情：7 节点轨迹（下载 AVIS/Shipper/BL → OCR 识别 → 写入 AVIS 模板 → 写入 BL 模板 → 导入 AVIS 模板 → 导入 BL 模板 → 上传原始文件）、字段面板（来源/置信度/原文定位）、证据附件（WORM 留痕）、R# 历史切换只读
- 重跑两级：节点重跑从选中节点起、前置检查点产物沿用；整单重跑生成 R#n+1（固化配置快照+携带生效修正值）；执行中拒绝（幂等）
- GLC 重跑无需人工上传：AVIS/Shipper/BL 由系统从 Portal 公邮重新获取，人工确认后即可整单重跑
- 兄弟任务互链：同 BL 跨周归并票可追溯

## EP-G6：邮件规则、模板配置与运行通知

**用户故事：** 作为平台管理员，我希望邮件监听规则、导入模板与对应关系表都在线版本化维护，每周运行结果能通知到业务同事，以便规则随业务变化及时生效、结果透明。

**验收要点：**

- 邮件监听三条规则（AVIS / Shipper / BL）可启停、可编辑（筛选条件+附件要求），保存写审计；停用后新邮件不再命中
- 配置中心版本化管理（上传新版本 v+1，旧版本保留可下载）：AVIS/BL 导入模板、PDC 与 Customer Code 对应关系表（104 个 Code 逐条维护）、IES Port 对应表、AVIS 对应口岸公邮清单
- 每周运行后按模板 TPL-C2-STATUS 从 Portal 公邮发出运行状态记录表：主题含运行周，正文表格字段可从状态报告 15 列目录中自选自排，收件人可配置（演示 9 人）
- 异常事件自动生成站内提醒；配置变更仅对后续 Run 生效（启动时快照）

# 第二部分：MBUSI 线（美线 · CMA CGM）

## EP-M1：每周大表导出与登记建票

**用户故事：** 作为业务操作员，我希望平台每周一自动从美国中央仓网站导出 gvShipLog 大表，筛出上周新增逐票登记建票并拆分子表，以便不再人工对表、拆行、建文件夹。

**验收要点：**

- 每周一定时触发（默认时刻 OPEN-M9），大表双通道获取：网站导出 / 指定位置读取（D4 通道可配置，权限受限时改读 T 盘报告）
- 按 O 列 Created 筛上周一至周日新增，与状态报告美线 sheet 对碰防重
- 每个 Booking No. 的行集拆分为单票子表 `Shipping log information_<Booking No.>.xlsx`，按 PDC+ETA 建票文件夹（PDC/ETA 缺失转人工）
- **大表先行**：登记成功即建 Task + Run#1（登记是建票条件，邮件匹配不是）；登记行回写大表（C/D/E/F/G 列）
- 前两个节点为批量级节点（下载大表、筛新增+登记+拆分），产物本轮共享；单票重跑与手动建票不触发它们（手动建票从填 Shipping Log 节点起跑）

## EP-M2：提单邮件匹配与字段识别

**用户故事：** 作为业务操作员，我希望系统按标题精确匹配 CMA CGM 提单邮件并识别提单字段，匹配不上就挂起等我处理，以便不错单、不漏单。

**验收要点：**

- 仅按标题「CMA CGM - 海运提单(Seaway Bill)可供使用」搜索公邮（发件过滤已取消，靠业务自动 Forward）
- G1 匹配闸口：提单 Booking No. 与大表已登记**精确匹配**才放行；不匹配→挂起"待上传-漏数"，走漏数处理区（EP-M4）
- 附件先入暂存台账（pending），同 BL 重复邮件保留最新版；匹配成功后重命名 `BL_<BL号>.pdf` 入票文件夹
- OCR 识别提单字段（Booking No. / 箱号 / 箱型 / 封号 / 件数 / VOL / Load / 船名航次等，F-01~F-15），字段带来源（系统取值/OCR/规则）、置信度与原文定位
- G2 质量闸口：字段低置信（阈值建议 0.85，OPEN-M22）或子表与提单核对不一致→"有差异"待人工
- MBUSI 不涉及危险品判断，DG 标识固定 N

## EP-M3：模板生成与 IES+ 导入

**用户故事：** 作为业务操作员，我希望系统自动填好 Shipping Log 与 BL 两张模板并导入 IES+ 生成预报和台账，遇到差异记录下来继续走，以便每票处理不中断、全程有痕迹。

**验收要点：**

- Shipping Log 模板基础字段取自 gvShipLog（箱级展开），VOL/Load 留空待 BL 回填；BL 模板 9 列取自提单 PDF
- VOL/Load **必须取自 BL**（GROSS WEIGHT(19) / MEASUREMENT(20)，优先级 OPEN-M10）回填 Shipping Log，两模板必填校验通过才允许导入
- 导入 Shipping Log：按 BOL 查 IES+ 发票 → 批量导入 → G3 绿灯闸口，绿灯才上传；不过 FAILED 转人工
- 生成预报：全选发票，预报信息取自提单，港口经 IES Port 对应表转换
- 导入 BL：集装箱信息导入 → **差异弹窗完整捕获回写「BL different」，不阻断**；无差异→生成台账；仅弹窗无法解析才置失败转人工
- 上传 BL PDF 到 IES+ 文档资料并保存（文件类别 OPEN-M14），回写状态报告；对外动作（台账已生成 / BL PDF 已上传）发生后整单重跑仅 MANAGER 并弹确认

## EP-M4：漏数挂起与差异人工协同

**用户故事：** 作为业务操作员，我希望大表漏数或子表与提单不一致的票有明确的人工处理闭环，补登后能续跑，以便异常票不积压、不丢失。

**验收要点：**

- 漏数票（邮件先到而大表未登记，或子表漏行）：建挂起 Task（待上传-漏数），台账保持 pending，不删不处理、多轮等待
- 任务详情漏数处理区三操作：确认续跑（先复核大表已登记，否则阻断）/ 继续等待 / 标记无效（撤销仅 MANAGER，OPEN-M13）
- 差异票（Shipping Log 漏数或集装箱信息差异）转入人工引导：先删除 IES+ 已生成的预报、线下确认差异，在 OCR 节点**上传更新后的 shipping log 子表**（自动存至对应 PDC 目录），数据齐备后手动重跑
- 上传中心提供漏数补登子表上传入口；补登更新 Created 不回溯，下轮捕获后从匹配节点续跑
- 字段修正仅留痕不审批，修正值随下次重跑生效

## EP-M5：任务跟踪、核查与重跑

**用户故事：** 作为业务操作员，我希望在工作台和任务中心按运行周掌握每票状态，在详情页核对字段与原文，并能按需重跑，以便日常只盯异常票、处理有依据。

**验收要点：**

- 工作台按 Case2-MBUSI 展示统计卡与调度信息条、"立即补跑"（OPERATOR 是否可触发 OPEN-M18），点卡穿透任务中心
- 任务中心：状态 chips（"待人工处理"聚合口径同 GLC）、任务日历、库房（PDC）/单号（Booking Number）/执行时间筛选、批量下载/批量重跑/导出/新建任务
- 任务详情：10 节点轨迹（下载 gvShipLog → 拆分子表 → 填 Shipping Log → 下载邮件附件 → OCR 识别 → 填 BL 模板 → 导入 Shipping Log → 生成预报 → 导入 BL 模板 → 上传 BL PDF）、字段面板、证据附件（WORM）、R# 历史切换只读
- 重跑两级：节点重跑从最近检查点续跑（N1/N2 批量节点不重跑）；整单重跑从填 Shipping Log 节点起跑、生成 R#n+1（配置快照+携带修正值）；执行中拒绝（幂等）
- MBUSI 重跑前置提示：需先删除 IES+ 已生成的预报并上传更新后的子表，数据准备完整后手动触发重新执行

## EP-M6：邮件规则与配置维护

**用户故事：** 作为平台管理员，我希望提单邮件监听规则、导入模板与对应关系表在线版本化维护，异常通过站内提醒触达，以便规则随业务变化及时生效。

**验收要点：**

- 邮件监听规则 R-MBUSI-BL（标题关键词 + 附件要求 PDF）可启停、可编辑，保存写审计
- 配置中心版本化管理：Shipping Log / BL 导入模板、PDC 对应关系表（与 GLC 共用一份）、IES Port 对应表、**网站导出通道配置**（D4，MBUSI 特有）
- MBUSI 不外发运行状态邮件（PRD 口径），异常与结果经站内提醒触达；原型中的外发模板差异见 §三 D-1
- 配置变更仅对后续 Run 生效（启动时快照）

# 第三部分：两线共用

## EP-S1：存档与追溯

**用户故事：** 作为业务操作员或审计员，我希望每票的过程文件按固定目录归档、平台内可浏览，状态报告逐票回写，以便追溯取证不用翻 T 盘。

**验收要点：**

- 目录四级：PDC → GLC 或 MBUSI → 运行周（ISO 周）→ 票文件夹；GLC 票夹命名 `Shippers Ref + OOLU + BL No. + ETA [+ DG]`，MBUSI 票夹命名 `Booking No. + ETA`
- GLC 票夹含 AVIS.xlsx / BL.xlsx / Avis 原件 / BL 原件（DG 加 Shippers_Decl）；MBUSI 票夹含 BL.xlsx / Shipping Log.xlsx / 单票子表 / HAWB 原件
- 状态报告（AVIS BL status report）按时机矩阵逐列回写，重跑对同 BL 同列覆盖写；回写失败入队重试并告警（E5002）
- Share Point 页平台内只读浏览目录树与文件，目录按修改日期倒序

## EP-S2：审计与合规

**用户故事：** 作为审计员，我希望以只读身份核查全量证据链与审计日志，以便完成合规审查；每票的自动执行、人工修正、对外动作都有据可查。

**验收要点：**

- 审计员全部页面只读，无写入口；调用写接口服务端拒绝并记录决策（E1004）
- 证据分 trigger/process/operation 三类（EV-T/EV-P/EV-O 前缀），带 hash 防篡改、WORM 留痕
- 审计日志含时间/操作人/动作/对象/入口五要素，可搜索；授权决策记录含主体/动作/资源/允许|拒绝/策略版本
- 职责分离：主管无字段修正权、操作员无对外动作确认权；修正仅留痕无审批；凭证不入日志
