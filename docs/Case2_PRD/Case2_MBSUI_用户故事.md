# 第一部分：MBSUI 正向线（每周）

## EP-M1：每周大表导出与登记建票

**用户故事：** 作为业务操作员，我希望平台每周一自动从美国中央仓网站导出 gvShipLog 大表，筛出上周新增逐票登记建票并拆分子表，以便不再人工对表、拆行、建文件夹。

**验收要点：**

- 每周一定时触发（默认时刻 OPEN-M9），大表双通道获取：网站导出 / 指定位置读取（D4 通道可配置，权限受限时改读 T 盘报告）
- 按 O 列 Created 筛上周一至周日新增，与状态报告美线 sheet 对碰防重
- 每个 Booking No. 的行集拆分为单票子表 `Shipping log information_<Booking No.>.xlsx`，按 PDC+ETA 建票文件夹（PDC/ETA 缺失转人工）
- **大表先行**：登记成功即建 Task + Run#1（登记是建票条件，邮件匹配不是）；登记行回写大表（C/D/E/F/G 列）
- 前两个节点为批量级节点（下载大表、筛新增+登记+拆分），产物本轮共享；单票重跑与手动建票不触发它们（手动建票从填 Shipping Log 节点起跑）

## EP-M2：提单邮件匹配与字段识别

**用户故事：** 作为业务操作员，我希望系统按标题精确匹配 CMA CGM 提单邮件并识别提单字段，匹配不上就挂起等我处理，以便不错单、不漏单。

**验收要点：**

- 仅按标题「CMA CGM - 海运提单(Seaway Bill)可供使用」搜索公邮（发件过滤已取消，靠业务自动 Forward）
- G1 匹配闸口：提单 Booking No. 与大表已登记**精确匹配**才放行；不匹配→挂起"待上传-漏数"，走漏数处理区（EP-M4）
- 附件先入附件台账（平台内部存储，pending），同 BL 重复邮件保留最新版；匹配成功后重命名 `BL_<BL号>.pdf` 入票文件夹
- OCR 识别提单字段（Booking No. / 箱号 / 箱型 / 封号 / 件数 / VOL / Load / 船名航次等，F-01~F-15），字段带来源（系统取值/OCR/规则）、置信度与原文定位
- G2 质量闸口：字段低置信（阈值建议 0.85，OPEN-M22）或子表与提单核对不一致→"有差异"待人工
- MBSUI 不涉及危险品判断，DG 标识固定 N

## EP-M3：模板生成与 IES+ 导入

**用户故事：** 作为业务操作员，我希望系统自动填好 Shipping Log 与 BL 两张模板并导入 IES+ 生成预报和台账，遇到差异记录下来继续走，以便每票处理不中断、全程有痕迹。

**验收要点：**

- Shipping Log 模板基础字段取自 gvShipLog（箱级展开），VOL/Load 留空待 BL 回填；BL 模板 9 列取自提单 PDF
- VOL/Load **必须取自 BL**（GROSS WEIGHT(19) / MEASUREMENT(20)，优先级 OPEN-M10）回填 Shipping Log，两模板必填校验通过才允许导入
- 导入 Shipping Log：按 BOL 查 IES+ 发票 → 批量导入 → G3 绿灯闸口，绿灯才上传；不过 FAILED 转人工
- 生成预报：全选发票，预报信息取自提单，港口经 IES Port 对应表转换
- 导入 BL：集装箱信息导入 → **差异弹窗完整捕获回写「BL different」，不阻断**；无差异→生成台账；仅弹窗无法解析才置失败转人工
- 上传 BL PDF 到 IES+ 文档资料并保存（文件类别 OPEN-M14），回写状态报告；对外动作（台账已生成 / BL PDF 已上传）发生后整单重跑仅 MANAGER 并弹确认

## EP-M4：漏数挂起与差异人工协同

**用户故事：** 作为业务操作员，我希望大表漏数或子表与提单不一致的票有明确的人工处理闭环，补登后能续跑，以便异常票不积压、不丢失。

**验收要点：**

- 漏数票（邮件先到而大表未登记，或子表漏行）：建挂起 Task（待上传-漏数），台账保持 pending，不删不处理、多轮等待
- 任务详情漏数处理区三操作：确认续跑（先复核大表已登记，否则阻断）/ 继续等待 / 标记无效（撤销仅 MANAGER，OPEN-M13）
- 差异票（Shipping Log 漏数或集装箱信息差异）转入人工引导：先删除 IES+ 已生成的预报、线下确认差异，在 OCR 节点**上传更新后的 shipping log 子表**（自动存至对应 PDC 目录），数据齐备后手动重跑
- 上传中心提供漏数补登子表上传入口；补登更新 Created 不回溯，下轮捕获后从匹配节点续跑
- 字段修正仅留痕不审批，修正值随下次重跑生效

## EP-M5：任务跟踪、核查与重跑

**用户故事：** 作为业务操作员，我希望在工作台和任务中心按运行周掌握每票状态，在详情页核对字段与原文，并能按需重跑，以便日常只盯异常票、处理有依据。

**验收要点：**

- 工作台按 Case2-MBUSI 展示统计卡与调度信息条、"立即补跑"（OPERATOR 是否可触发 OPEN-M18），点卡穿透任务中心
- 任务中心：状态 chips（"待人工处理"=待上传∪有差异∪失败的聚合口径）、任务日历、库房（PDC）/单号（Booking Number）/执行时间筛选、批量下载/批量重跑/导出/新建任务
- 任务详情：10 节点轨迹（下载 gvShipLog → 拆分子表 → 填 Shipping Log → 下载邮件附件 → OCR 识别 → 填 BL 模板 → 导入 Shipping Log → 生成预报 → 导入 BL 模板 → 上传 BL PDF）、字段面板、证据附件（WORM）、R# 历史切换只读
- 重跑两级：节点重跑从最近检查点续跑（N1/N2 批量节点不重跑）；整单重跑从填 Shipping Log 节点起跑、生成 R#n+1（配置快照+携带修正值）；执行中拒绝（幂等）
- MBSUI 重跑前置提示：需先删除 IES+ 已生成的预报并上传更新后的子表，数据准备完整后手动触发重新执行

## EP-M6：邮件规则与配置维护

**用户故事：** 作为平台管理员，我希望提单邮件监听规则、导入模板与对应关系表在线版本化维护，异常通过站内提醒触达，以便规则随业务变化及时生效。

**验收要点：**

- 邮件监听规则 R-MBUSI-BL（标题关键词 + 附件要求 PDF）可启停、可编辑，保存写审计
- 配置中心版本化管理（上传新版本 v+1，旧版本保留可下载）：Shipping Log / BL 导入模板、PDC 对应关系表（与 GLC 共用一份）、IES Port 对应表、**网站导出通道配置**（D4，MBSUI 特有）
- MBSUI 不外发运行状态邮件（PRD 口径），异常与结果经站内提醒触达；原型中的外发模板差异见 §四 D-1
- 配置变更仅对后续 Run 生效（启动时快照）

# 第二部分：MBUSI-R 反向核对（每日 · 新增平行 case）

> 2026-10-16 会议（K44/K45 分工）新增。覆盖正向盲区：正向以"大表登记 / 收邮件"为起点，识别不到**美国大表早已登记、但 BL PDF 邮件一直未收到**的漏收票。反向核对以"下载美国大表"为起点反向比对，把这类票拉成差异清单供业务跟进。与正向线**无任何触发/数据关联**，轻量核对链、**无 IES 交互**。

## EP-R1：每日大表导出与 BL 号集合获取

**用户故事：** 作为业务操作员，我希望平台每日自动导出美国 gvShipLog 大表并取出本批全部 BL 号（Booking Number）集合，以便核对有权威的对向数据底账、不依赖人工导表。

**验收要点：**

- 每日定时触发（具体时点可配置，默认时刻待定，见 §五 R-OPEN-1）
- 大表获取通道与正向线一致：网站导出 / 指定位置读取（D4 可配置）；获取失败本轮终止并告警，随次日调度自愈
- 从 gvShipLog 提取 Booking Number 列形成本批 BL 号集合（即 BL 号集合），与状态报告美线 sheet 登记口径一致
- 本轮集合留快照（批次号 + 取数时间），供差异清单追溯与轮次间比对

## EP-R2：邮件标题反查与时间维度比对

**用户故事：** 作为业务操作员，我希望系统按大表里的每个 BL 号反查平台公邮标题，确认对应 BL PDF 邮件是否已收到，以便把"大表有、邮件没收到"的票自动挑出来。

**验收要点：**

- 按本批 BL 号逐一检索平台公邮（CMA 转发）邮件标题，确认该 BL 的提单邮件收件情况
- **卡时间维度比对**：大表 BL 号集合 vs 已收 BL 邮件集合，按登记时间/邮件到达时间设定等待窗口（窗口时长待定，见 §五 R-OPEN-2），避免因邮件正常在途造成误报
- 比对结论二分：已收（本轮通过，不产生待办）/ 未收（进差异清单，EP-R3）
- 与正向线互不触发：比对结果不回写正向票、不触发电机续跑；正向 G1 闸口的"漏数挂起"仍由正向线自己承担
- 核对链无 IES 交互、无对外动作，失败票不设重跑机制，随次日调度自愈

## EP-R3：差异清单输出与漏收跟进闭环

**用户故事：** 作为业务操作员，我希望"大表已登记但 BL PDF 未收到"的票每日自动汇总成差异清单并能被我看到、跟进、销项，以便漏收邮件及时发现、及时催单。

**验收要点：**

- 每轮输出差异清单：大表已登记但 BL PDF 未收到的票，含 Booking No. / PDC / 大表登记时间 / 已等待天数
- 差异结果在任务中心 / 报表可见（具体落点：大表异常反馈列 / 独立报表 / 任务中心条目，待与开发确认，见 §五 R-OPEN-3），并生成站内提醒
- 同一 BL 号连续多轮未收：差异清单按最新状态更新（等待天数累进），不重复堆叠条目
- 业务线下跟进（向 CMA 催发提单邮件）；后续该 BL 邮件到达后，正向线 G1 匹配放行、差异条目自动销项（销项口径随落点方案一并确认）
- 差异清单全程留痕（产出批次 / 命中票 / 销项时间），纳入审计范围（EP-S2）

# 第三部分：共用

## EP-S1：存档与追溯

**用户故事：** 作为业务操作员或审计员，我希望每票的过程文件按固定目录归档、平台内可浏览，状态报告逐票回写，以便追溯取证不用翻 T 盘。

**验收要点：**

- 目录四级：PDC → MBUSI → 运行周（ISO 周）→ 票文件夹；票夹命名 `Booking No. + ETA`
- 票夹含 BL.xlsx / Shipping Log.xlsx / 单票子表 / BL 原件 PDF
- 状态报告（AVIS BL status report 美线 sheet）按时机矩阵逐列回写，重跑对同 BL 同列覆盖写；回写失败入队重试并告警（E5002）
- 反向核对产物（大表批次快照、差异清单）按批次归档，路径规则随差异清单落点方案一并确定
- Share Point 页平台内只读浏览目录树与文件，目录按修改日期倒序

## EP-S2：审计与合规

**用户故事：** 作为审计员，我希望以只读身份核查全量证据链与审计日志，以便完成合规审查；每票的自动执行、人工修正、对外动作都有据可查。

**验收要点：**

- 审计员全部页面只读，无写入口；调用写接口服务端拒绝并记录决策（E1004）
- 证据分 trigger/process/operation 三类（EV-T/EV-P/EV-O 前缀），带 hash 防篡改、WORM 留痕；反向核对的大表快照与差异清单同属证据链
- 审计日志含时间/操作人/动作/对象/入口五要素，可搜索；授权决策记录含主体/动作/资源/允许|拒绝/策略版本
- 职责分离：主管无字段修正权、操作员无对外动作确认权；修正仅留痕无审批；凭证不入日志
