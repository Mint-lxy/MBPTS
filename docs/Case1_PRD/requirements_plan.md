## 需求摘要（步骤9完成后填写）

### 产品定义
- **产品名称**: UC34 Case 1 · 危险品托运清单自动生成
- **所属系统**: MBPTS 智能作业平台（Portal + 后台 RPA 执行引擎）
- **功能定位**: 替代人工在 IES+ 中筛选、匹配、制单、上传、通知的全流程自动化，以一个 HAWB/BL 为一票任务粒度
- **使用端**: PC Web Portal（业务用户）+ 后台 RPA 无人值守执行

### 核心价值
| 价值维度 | 价值描述 | 受益人群 |
|---------|--------|---------|
| 效率 | 每日/每周定时自动完成托运清单制作与上传，消除人工逐票操作 | IO 同事 |
| 合规 | 危险品道路运输托运清单合规出具，全程留痕可审计 | 业务/合规 |
| 透明 | Portal 实时状态、失败可追踪可重提、运行结果邮件通达 | 业务主管 |

### 产品范围

**包含范围：** F001-F022 全部（按 BRD 全量，含 Type1-4 / SET / 4kg 与 5L/5KG 阈值，原型未覆盖处在 PRD 标注"原型缺口"）。

**不包含范围（后续迭代）：**
- IES+ 系统本身的功能改造
- 邮件监听触发（Case1 为定时触发，邮件中心监听模块本期为空）
- 上传中心手工数据补充（Case1 无需上传文件）
- UC26/UC64 及 Case2-5 的内容
- 存档存储路径的最终技术选型（T盘/SharePoint，TBD）

### 业务目标与成功指标
| 目标 | 描述 | 优先级 |
|------|------|--------|
| 全自动制单 | 定时任务无人值守完成筛选→制单→上传→通知 | P0 |
| 异常可恢复 | 失败任务可查询、修正数据后可重提 | P0 |
| 全程留痕 | 每步运行结果、文件、操作均有记录 | P0 |

| 指标 | 目标值 | 测量方法 |
|------|-------|---------|
| 定时任务成功率 | ≥ 95%（剔除源数据问题） | 治理台失败率统计 |
| 单票处理时长 | 较人工显著下降（基线待补） | Run 耗时统计 |
| 清单上传状态邮件触达 | 每次运行 1 封，100% 发送 | 邮件外发审计 |

### 非功能性需求
- 运行时间可配置（Portal 可根据实际运行时长调整运行时间，BRD 注明）
- 定时来源任务时间统一显示当天 00:00（演示口径，正式以调度配置为准）
- 证据/产物 WORM 防篡改留存；历史 Run 不可变只读
- RBAC 由 Alice 身份系统管理，平台只读展示；UI 显隐不替代服务端授权
- 邮件收件人清单、Data base 附表、清单模板均需配置化，支持人员/供应商变动

### 约束与假设
- IES+ 集成方式为 RPA UI 自动化；批量/逐票处理待 vendor 评估（TBD）
- 调度口径：空运每日 00:00；海运每周一 00:00 取上周一~周日；均保留手动触发；运行时间可配置调整
- 数据出错场景已知四类：document 缺失、UN 标识改变、主数据变化、运单号改变
- 一票 = 一个 HAWB/BL 对应一份托运清单
- UN No. 为空 → NA 无需制作；UN No. 为 SET → 按 Y 逻辑并走套装核验
- Type3 全票为 N、Type4 全票 ≤4kg、或混合待定均确认无需 → "N_ Not required"
- UN3082/UN3077 且未下载到 Shippers_Decl → Remark"含UN3082/UN3077，需进一步核查包装规格是否大于5L/5KG"
- 无 SDS 情况 → 邮件状态表 Remark 列反馈记录

### 风险与待确认
- R1: IES+ 页面结构变更导致 RPA 失效 → 需监控与快速修复机制
- R2: Data base 附表版本与业务实际不一致 → 配置版本管理+变更审计
- R3: SDS 第14章格式多样 → OCR/解析规则需覆盖多种格式（BRD 已列示例）
- R4: 存档路径迁移（公司政策）→ 地址配置化
- Q5-Q8 待澄清（见澄清文档）
