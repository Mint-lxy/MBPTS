# 第一部分：产品概述

## 1.1 产品定义

- **名称**：马来西亚 MBPLAP 发票与预报创建
- **定位**：forwarder（TV SCS）预报邮件到件后，自动完成附件识别改名、IES+ 发票创建、PDF 上传、预报创建、附件挂载、回复邮件与存档
- **使用端**：平台公邮 + Portal + IES+

## 1.3 产品范围

**包含**：触发双条件（标题"MBPLAP Pre-alert"∧@tvsscs.com）、四类附件识别（关键字+内容兜底）、规范命名、INV&DN 模板生成与上传、Warning 捕获入台账（附件 3）、预报创建与附件类型挂载（HAWB/MSDS/Shipper）、回复邮件（附件 5 loop）、日期/HAWB 存档、年度台账。

**不包含**：Case 3 的系统差异"硬性人工节点"（Q33=A 已按 Final BRD 作废该旧口径）；forwarder 侧流程变更；对 IES+ 的 AI 二次校验（Q34=B：以 IES 事件+Portal Log 为准，截图仅作证据留存）。

---

# 第二部分：业务背景与目标

## 2.1 业务问题

1. 每收到 MBPLAP 预报邮件需手工分类附件、命名、建发票、生成预报、回邮件，频密且循环类比多
2. 四类附件命名规则惯性强，人工命名错误会引发 IES 检索失败

## 2.2 目标与指标

| 目标 | 描述 | 优先级 |
|---|---|---|
| 邮件到件即自动建单 | 收件后免有人工分类/命名/录入 | P0 |
| 异常不静默 | Warning 一律入台账 Remark 列 | P0 |
| 循环防自触发 | 回复邮件不再触发新任务 | P0 |

指标（Open Item）：≥90% / 85%。

# 第五部分：用户故事

### US-C3-001：邮件触发与识别

**作为** 系统 **在** 平台公邮收到 forwarder 邮件时 **我想要** 双条件命中即起流程 **以便于** 不乱触发也不漏件。

- AC1: 标题含"MBPLAP Pre-alert" ∧ 后缀=@tvsscs.com（均可配置）
- AC2: 本流程自己发出的回复邮件不会触发新任务（发件人条件排除）
- AC3: 定期搜索为 BRD 兜底备径，默认关闭（Q31=A）
- E1: 标题缺关键字惯例（客户偶发）→命中失败不建任务，平台按邮件规则走待归类池

### US-C3-002：附件识别与规范命名

- AC1: 发票=文件名第二数字段以 1100 开头；pre-alert=含 HAWB；SDS=含 SDS；shipper=含 shipper；全未中→文件内容立案（Q32=B：仍不入四类则归 Others 继续不阻断）
- AC2: 重命名规则（发票号/HAWB_分单号/MSDS_分单号/Shippers_Decl_分单号；无分单号用主单号）
- E1: 同名文件重复→指纹防重；E2為函件附件名混乱→内容立案再分类

### US-C3-003：IES+ 发票创建与批量上传

- AC1: 附件 1 提取需求+附件 2 模板格式→生成 INV&DN 文件
- AC2: 进口管理-发票信息-导入 INV&DN-上传；Warning 全量捕获写附件 3
- AC3: 按发票号搜索→批量上传 PDF 发票；无需 AI 二次校验，以 IES 事件+Portal Log 为准（Q34=B，截图仅作证据）
- E1: 发票号与 PDF 不匹配→异常 Remark；E2: 上传中途网络断→不冒充成功，状态 UNKNOWN

### US-C3-004：预报创建与附件挂载

- AC1: 查询分单全部发票（IES 每页强制 100 条，Q35=A）→全选→生成预报→附件 4 字段→确定
- AC2: 预报修改→文档资料上传：分单（无→主单）=HAWB 类别；MSDS=Others；Shipper=Shipper decl
- E1: 预报 Warning→记录 Remark 后继续后续步

### US-C3-005：回复邮件与存档

- AC1: 回复原邮件按附件 5 loop 收件人，正文=固定问候+本票状态表
- AC2: 存档=操作日期一级 + HAWB 二级（主分单/发票/导入模板/MSDS/Shipper）+ 附件 3 日累积+年度分册
- E1: 发送失败→重试+告警（F-NT-004），台账不缺行

# 第八部分：数据需求
